설치

Windows 설치 프로그램

  1. 릴리스 페이지에서 debutkit-버전-windows-x64-setup.exe를 다운로드해 실행합니다.
  2. 추가 작업 화면에서 필요한 항목을 선택합니다. 자동 클립을 사용할 경우 ffmpeg 다운로드(약 115 MB)를 선택합니다.
  3. 설치가 끝나면 시작 메뉴의 debutkit을 실행합니다.
  • 현재 사용자 계정에 설치되며 관리자 권한이 필요하지 않습니다.
  • 명령줄 도구 debutkit.exe는 설치 폴더에 포함됩니다.
  • 제거는 Windows 설정의 앱 목록에서 진행합니다. 다운로드한 ffmpeg는 다른 프로그램과 함께 사용하는 폴더에 저장되므로 제거 대상에서 제외됩니다.
  • 코드 서명을 적용하지 않아 SmartScreen 경고가 표시될 수 있습니다. 이 경우 추가 정보를 선택한 뒤 실행합니다.

Windows 압축 파일

  1. 릴리스 페이지에서 debutkit-버전-windows-x64.zip을 다운로드합니다.
  2. 원하는 폴더에 압축을 해제합니다.
  3. debutkit-gui.exe(설정 마법사) 또는 debutkit.exe(명령줄)를 실행합니다.

macOS, Linux 실행 파일

운영체제파일실행
macOS(Apple Silicon)debutkit-버전-macos-arm64.zip압축 해제 후 debutkit.app 실행. 명령줄은 debutkit.app/Contents/MacOS/debutkit
Linux(x64)debutkit-버전-linux-x64.tar.gz압축 해제 후 debutkit/debutkit-gui(설정 마법사) 또는 debutkit/debutkit(명령줄) 실행
  • macOS: 공증을 적용하지 않아(임시 서명만 적용) 첫 실행 시 Gatekeeper 경고가 표시됩니다. Finder에서 debutkit.app을 우클릭한 뒤 열기를 선택합니다.
  • Linux: Qt 실행에 그래픽 라이브러리가 필요합니다. Ubuntu, Debian은 sudo apt install libxcb-cursor0 libxkbcommon-x11-0으로 설치합니다.
  • OBS 원격 제어, 채팅창, 자동 클립의 동작은 Windows와 같습니다. Linux에서 아바타 창 캡처 소스가 없는 OBS는 아바타 소스를 생략하고 안내합니다.

설정 마법사

시작 메뉴의 debutkit, debutkit-gui 또는 debutkit gui로 실행합니다. 왼쪽 단계 목록이나 다음 버튼으로 이동합니다.

단계내용
PC 점검이 단계를 열면 자동으로 점검. ffmpeg가 없으면 ffmpeg 다운로드 버튼 표시(Windows). 업로드 속도 측정 버튼
캐릭터캐릭터 등록(파일, 폴더), PNG 이미지로 만들기, 방송에 사용할 캐릭터 지정, 3D 캐릭터 동작(기본 동작, 후원 반응), VTube Studio와 Warudo로 보내기, 사용 조건 확인
OBS 장면WebSocket 포트, 비밀번호, 아바타 프로그램을 지정해 장면 생성
채팅과 알림플랫폼별 채널 입력, 치지직 로그인, 자동 클립과 채팅 명령 선택 후 오버레이 시작. 실행 중 추첨 조작 화면, 로고 만들기 열기
마무리다음 할 일(시작하기 화면 열기), 단계별 준비 상태, 자동 클립 저장 폴더, 새 버전 확인, 저장한 설정 삭제, 문제 제보(점검 결과 복사, 기록 폴더 열기)
  • 설정 마법사를 닫으면 오버레이와 자동 클립도 함께 종료됩니다.
  • OBS 비밀번호, 치지직 Client Secret, YouTube API 키는 파일에 저장하지 않습니다.

저장한 설정

  • 오버레이 시작, 장면 생성, 창 닫기 시점에 채널 주소, 포트, 선택 항목을 이 PC에 저장합니다.
  • 다음 실행 시 저장한 값을 불러오며, 채널을 저장한 경우 채팅과 알림 단계에서 시작합니다. 방송마다 오버레이 시작만 누르면 됩니다.
  • 저장 위치: Windows %APPDATA%\debutkit\settings.json, macOS ~/Library/Application Support/debutkit/settings.json, Linux ~/.config/debutkit/settings.json
  • 삭제: 마무리 단계의 저장한 설정 삭제 버튼 또는 debutkit settings --clear

방송 시작 버튼

방송에 필요한 프로그램(OBS, VTube Studio 등), 폴더, 사이트(치지직 스튜디오 등)를 정해 둔 순서로 켜고, 메신저와 게임 런처처럼 방송에 방해되는 프로그램은 먼저 끕니다. 방송이 끝나면 꺼 둔 프로그램을 다시 켭니다.

  1. 설정 마법사 마무리 단계의 방송 시작 버튼 카드에서 세팅 편집을 누릅니다.
  2. 켤 것 목록에 프로그램, 바로가기, 폴더를 끌어다 놓거나 파일, 폴더, 사이트 버튼으로 추가합니다. 위에서부터 차례로 켜며, 항목마다 다음 항목까지 기다리는 시간을 정합니다(무거운 프로그램은 넉넉하게).
  3. 끌 것 목록에는 켜진 프로그램에서 고르거나 프로그램 이름(예: Discord.exe, KakaoTalk.exe)을 입력합니다. 바로가기를 놓으면 대상 프로그램 이름으로 바꿉니다.
  4. 프로그램 창을 원하는 자리와 크기(모니터, 최대화 포함)로 둔 뒤 지금 창 위치 기억을 누르면 다음부터 그 자리로 엽니다(Windows).
  5. 저장한 뒤 방송 전에 켜기, 방송이 끝나면 방송 끝을 누릅니다.
세팅게임, 작업, 노래 방송처럼 상황별로 여러 개. 복제해서 금방 만들고 백업 파일로 다른 PC에 옮김
끄는 방식창 닫기 요청을 보내고 6초 안에 남아 있으면 강제 종료. 운영체제, 보안 프로그램, debutkit, 보호 목록의 프로그램은 끄지 않음
이미 켜진 프로그램다시 켜지 않음(선택: 창만 기억한 자리로 옮기기)
사이트Edge(없으면 Chrome)의 새 창으로 열고 기억한 자리로 옮김
다시 켜짐 알림꺼 둔 프로그램이 방송 중에 다시 켜지면 카드에 표시(선택: 다시 끄기)
켠 뒤선택: OBS WebSocket 연결 확인(최대 60초), 채팅과 알림 단계 설정으로 오버레이 시작
방송 끝이번 방송에 끈 프로그램을 다시 켜고 감시를 멈춤(세팅에서 끌 수 있음)

명령줄: debutkit launch add 방송 "C:/Program Files/obs-studio/bin/64bit/obs64.exe" https://studio.chzzk.naver.com, debutkit launch add 방송 Discord.exe --stop, debutkit launch(켜기), debutkit launch end(방송 끝). 창 위치는 debutkit launch remember. macOS, Linux는 켜기와 끄기만 사용할 수 있습니다.

캐릭터

방송에 사용할 캐릭터를 등록하고 사용 조건을 확인합니다. PNGTuber와 3D(VRM, GLB, FBX)는 debutkit 캐릭터 화면으로 바로 방송하고, Live2D는 VTube Studio로 보내 방송합니다.

종류별 처리

종류등록할 파일방송
PNGTuber입 다문 이미지와 입 벌린 이미지(투명 PNG). 눈 감은 이미지 2장 선택debutkit 캐릭터 화면. 말하면 입 벌린 이미지로 바뀌고 무작위로 눈 깜빡임
3D(VRM 0.x, 1.0).vrm 파일debutkit 캐릭터 화면(입 움직임, 눈 깜빡임, 호흡, 웹캠 얼굴 추적). 손과 몸 추적이 필요하면 Warudo, VMagicMirror, VSeeFace(VRM 0.x만)
3D(GLB, FBX)사람 모양 뼈가 있는 .glb, .fbx(Mixamo, VRoid, Unreal, Blender, MMD 등의 뼈 이름). FBX 텍스처는 같은 폴더에 두거나 파일에 포함debutkit 캐릭터 화면(VRM과 같은 움직임). 다른 방송 프로그램에는 VRM 변환 필요
Live2Dmodel3.json이 있는 폴더 또는 zipVTube Studio. 방송 프로그램으로 보내기로 모델 폴더에 복사
Inochi2D.inp, .inxInochi Session에서 불러오기
  • 등록하면 파일을 이 PC의 캐릭터 보관함(설정 폴더의 characters)에 복사합니다.
  • VRM은 파일에 기록된 사용 조건(사용 허용 대상, 상업적 이용, 법인 사용)을 읽어 수익 방송이나 소속사 활동에 제한이 있으면 표시합니다. GLB, FBX, Live2D, PNG는 파일에 사용 조건이 없으므로 판매처, 제작자 약관을 직접 확인해야 합니다.
  • GLB, FBX에 입 모양이나 눈 감기 표정이 없으면 등록할 때 알려 줍니다. ARKit 표정(퍼펙트 싱크)이 있는 모델은 그 표정으로 입과 눈을 움직이고, 입 모양이 없고 턱 뼈가 있으면 턱을 움직입니다.
  • 바로 시험할 수 있도록 debutkit 기본 캐릭터 데비를 PNGTuber와 3D(VRM) 두 가지로 함께 제공합니다. 3D 데비는 CC0 VRoid 샘플의 색을 데비 색으로 바꾼 모델이며 누구나 방송, 수익 방송, 수정에 사용할 수 있습니다.

캐릭터 만들기

  • PNGTuber: 같은 크기의 투명 PNG로 입 다문 모습과 입 벌린 모습을 그린 뒤 설정 마법사의 PNG로 만들기를 사용합니다.
  • VRM으로 그림 만들기(설정 마법사 캐릭터 단계의 그림 만들기(VRM), 주소 /character/sheet)
    • 등록한 VRM을 이 PC에서 그림(모델 파일은 밖으로 보내지 않음)
    • 표정 시트: 정면, 3/4, 얼굴, 표정 7종(기본, 기쁨, 화남, 슬픔, 편안, 아, 눈 감음). 무대 배경, 시트 그림 저장 가능
    • 추천 자세: 편하게 서기, 손 인사, 허리에 손, 만세, A 자세(PNGTuber 4상태도 같은 자세)
    • 포즈 그림: 몸, 머리, 왼팔, 오른팔, 다리를 따로 골라 조합. 잠금과 랜덤 포즈, 표정, 각도(정면, 살짝 옆, 3/4)
    • 포즈 그림 저장: 1024x1536 PNG. 무대 배경을 끄면 투명(썸네일, 방송 화면 꾸미기에)
    • 관절 직접 돌리기: 관절(목, 머리, 어깨, 팔, 손목, 다리 등)을 골라 막대로 더 돌림. 오른쪽은 거울이라 같은 값이면 양쪽이 같은 동작
    • 자세 파일 불러오기: VRMA(동작 시점 고르기)와 MMD 포즈 파일 VPD. MMD 팔 각도로 팔 높이 보정. 파일은 브라우저 안에서만 읽음
    • MMD의 다리 IK로 만든 다리 자세는 VPD에 들어 있지 않으면 적용되지 않음(다리 뼈 회전이 있는 VPD만)
    • 내 자세 저장: 지금 자세를 이름으로 저장하고 다시 불러오기(이 PC 설정 폴더, 50개까지)
    • VMC로 자세 보내기: Warudo, VSeeFace, VMagicMirror의 VMC 받기(포트 39539)를 켜고 같은 VRM을 불러 둔 뒤 보내기 시작. 지금 자세와 표정이 그대로, 자세를 바꾸면 바로 반영
    • 얼굴 추적 VMC 송신(/vmc)과 함께 켜면 머리와 표정은 얼굴 추적 값. 이 화면을 닫으면 20초 안에 멈춤
    • PNGTuber 4상태(입 다묾, 입 벌림, 눈 감음, 입 벌리고 눈 감음)를 투명 배경 1024px로 만들어 바로 등록
    • 등록한 그림 캐릭터는 원본 VRM의 작성자와 사용 조건을 그대로 따름
    • VRoid Studio로 만든 VRM이면 그 품질 그대로 그림이 됨
    • 모델 점검: 감정 표정, 입 모양, 눈 깜빡임, 퍼펙트 싱크, 텍스처 무게(그래픽 메모리 추정)
    • 가벼운 사본: 텍스처를 1024px 이하로 줄인 새 캐릭터. 게임과 함께 방송할 때 그래픽 메모리 약 절반(원본은 그대로, 수정 금지 모델은 만들지 않음)
  • 3D: VRoid Studio(무료, 한국어, Windows와 macOS)에서 만든 뒤 VRM으로 내보냅니다. VSeeFace와 함께 사용할 경우 VRM 0.0, 소속사 활동 예정이면 법인 사용 조건을 정할 수 있는 VRM 1.0을 선택합니다.
  • Linux: VRoid Studio가 없으므로 Vket Avatar Maker(웹)나 Blender와 VRM Add-on을 사용합니다. Vket Avatar Maker로 만든 모델은 저작권이 HIKKY에 있고 법인, 소속사 사용은 HIKKY의 사전 확인이 필요합니다.
  • 뼈가 없는 3D 모델: Mixamo(무료, Adobe 계정)에서 자동으로 뼈를 넣고 FBX로 받아 등록합니다. Mixamo 원본 파일은 다른 사람에게 배포할 수 없습니다.
  • Live2D: Live2D Cubism Editor로 제작하거나, 부위별 레이어로 나눈 PSD를 리거에게 의뢰합니다. FREE 버전은 텍스처 1장, 파라미터 30개 등의 제한이 있습니다.
  • 도구별 가격, 라이선스, 파일 형식: CHARACTER.md

debutkit 캐릭터 화면으로 방송

  1. 캐릭터 단계에서 캐릭터를 선택하고 방송에 사용을 누릅니다.
  2. OBS 장면 단계에서 아바타 프로그램을 debutkit 캐릭터 화면으로 선택하고 장면을 생성합니다. 직접 추가할 때는 브라우저 소스 주소에 http://127.0.0.1:8790/character를 입력합니다.
  3. 채팅과 알림 단계에서 오버레이를 시작합니다. OBS 설정의 마이크 음량이 기준(기본 -40 dB)을 넘으면 캐릭터가 말하는 모습으로 바뀝니다.
  • 잡음에 입이 움직이면 기준을 높이고(-30 등), 말해도 반응하지 않으면 낮춥니다. 명령줄: debutkit overlay --voice-threshold -35
  • OBS 마이크 대신 다른 오디오 소스를 사용하는 경우 --voice-input 소스이름을 지정합니다.
  • 미리보기: 오버레이 실행 중 설정 마법사의 미리보기 버튼(말하기 동작 반복)
  • 기준 조정: 시작하기 화면(http://127.0.0.1:8790)의 캐릭터 화면 카드에서 현재 OBS 마이크 음량(dB)과 말하기 상태를 보면서 기준을 정합니다. 말하기 시험 버튼은 3초 동안 말하는 모습을 표시합니다.

웹캠 얼굴 추적

3D(VRM) 캐릭터의 머리 움직임, 양쪽 눈, 입, 웃음을 웹캠으로 추적합니다. PNGTuber는 눈 깜빡임과 입 벌림에 반영합니다. OBS 브라우저 소스는 카메라를 쓸 수 없어 추적은 일반 브라우저 창에서 합니다.

  1. 오버레이를 실행한 상태에서 설정 마법사의 얼굴 추적 창 열기를 누르거나 브라우저(Chrome, Edge)에서 http://127.0.0.1:8790/tracker를 엽니다.
  2. 추적 시작을 누르고 카메라 사용을 허용합니다. 카메라가 여러 대이면 목록에서 선택합니다.
  3. 추적 창은 열어 둔 채 OBS를 사용합니다. 창을 닫거나 최소화하면 0.6초 뒤 캐릭터가 기본 움직임으로 돌아갑니다.
  • 카메라 영상은 브라우저 창 안에서만 처리하고 숫자 값(머리 각도, 눈, 입, 웃음)만 debutkit 서버로 보냅니다. 영상은 저장하거나 전송하지 않습니다.
  • 추적에는 Google의 오픈소스 MediaPipe Face Landmarker(Apache-2.0)를 사용하며 프로그램에 포함되어 있습니다. MediaPipe에 들어 있는 사용 기록 전송은 추적 화면의 보안 정책으로 차단합니다.
  • 거울처럼 움직이기(기본)는 고개를 돌린 방향이 화면의 같은 쪽으로 보이게 합니다.
  • Live2D 캐릭터의 얼굴 추적은 VTube Studio가 담당합니다.

휴대폰 얼굴 추적(아이폰)

아이폰의 얼굴 인식 카메라(ARKit)로 추적한 머리 움직임과 표정 52개를 캐릭터에 반영합니다. 웹캠보다 눈, 입, 눈썹 움직임이 정확합니다. 휴대폰 앱은 iFacialMocap(App Store 유료, FaceMotion3D는 iFacialMocap 호환 모드) 또는 VTube Studio(아이폰, 아이패드)를 사용합니다.

  1. 휴대폰과 PC를 같은 Wi-Fi(공유기)에 연결합니다.
  2. 휴대폰 앱을 실행합니다. VTube Studio는 설정 첫 번째 탭 맨 아래의 3rd Party PC Clients를 켭니다. 앱 화면에 표시된 IP 주소를 확인합니다.
  3. 오버레이를 실행한 상태에서 설정 마법사의 휴대폰 얼굴 추적을 누르거나 브라우저에서 http://127.0.0.1:8790/phone을 엽니다.
  4. 앱 종류와 휴대폰 IP 주소를 입력하고 연결 시작을 누릅니다. 처음 연결할 때 Windows 보안 경고가 나오면 개인 네트워크를 허용합니다.
  5. 휴대폰을 비스듬히 둔 경우 화면을 정면으로 보는 자세에서 지금 자세를 정면으로를 누릅니다.
  • 연결 설정은 저장되어 다음 오버레이 실행 때 자동으로 시작합니다. 연결 끊기를 누르면 다음 실행부터 시작하지 않습니다.
  • 휴대폰 값을 받는 중에는 웹캠 추적 창의 값을 사용하지 않습니다.
  • 퍼펙트 싱크: ARKit 이름 표정(eyeBlinkLeft, jawOpen 등)을 가진 3D 캐릭터는 눈썹, 볼, 코, 혀까지 얼굴 전체가 움직입니다. 웹캠 추적도 같은 방식으로 반영합니다.
  • 머리가 반대로 돌면 거울처럼 움직이기를 바꾸고, 위아래가 반대면 위아래 반전을 선택합니다. 연결되지 않으면 Windows 네트워크 프로필(개인 네트워크), 아이폰의 로컬 네트워크 허용, 같은 앱을 받는 다른 프로그램(VSeeFace, Warudo 등) 종료를 확인합니다.

VMC 송신(Warudo, VSeeFace, VMagicMirror)

debutkit의 얼굴 추적 값(웹캠 추적 창, 휴대폰 얼굴 추적)을 VMC 프로토콜로 다른 프로그램에 보냅니다. 머리 회전, 양쪽 눈, 입, 웃음과 퍼펙트 싱크 표정 52개를 보냅니다.

  1. 받는 프로그램에서 VMC 수신을 켭니다(Warudo의 VMC 수신, VSeeFace의 VMC protocol receiver, VMagicMirror의 외부 트래킹). 포트는 기본 39539.
  2. 오버레이를 실행한 상태에서 설정 마법사 캐릭터 단계의 VMC 송신을 누르거나 http://127.0.0.1:8790/vmc를 엽니다.
  3. 주소(같은 PC는 127.0.0.1)와 포트를 확인하고 송신 시작을 누릅니다. 켜 두면 다음 오버레이 실행 때도 자동으로 시작합니다.
  • 받는 곳은 이 PC나 같은 네트워크의 내부 주소만 지정할 수 있습니다. 다른 PC로 보낼 때는 받는 PC의 방화벽에서 UDP 포트를 허용합니다.
  • 얼굴을 찾지 못하는 동안에는 보내지 않아 받는 프로그램이 마지막 자세를 유지합니다. 좌우가 반대로 움직이면 좌우 반전을 선택합니다.
  • 명령줄: debutkit vmc start --host 127.0.0.1 --vmc-port 39539, debutkit vmc status, debutkit vmc stop

debutkit 휴대폰 앱

휴대폰 앞면 카메라로 얼굴을 추적해 머리 움직임과 표정 52개를 PC로 보내는 debutkit 전용 앱입니다. 다른 회사 앱 없이 안드로이드 휴대폰으로도 휴대폰 얼굴 추적을 사용할 수 있습니다. PC 없이 휴대폰만으로 방송하는 방법은 휴대폰만으로 바로 방송을 참고합니다.

  1. 안드로이드: 릴리스 페이지의 debutkit-phone-버전-android.apk를 휴대폰에서 다운로드해 설치합니다(출처를 알 수 없는 앱 설치 허용). 아이폰: 앱 스토어 배포 전이므로 Mac과 Xcode로 직접 빌드합니다(저장소의 mobile/ios/README.md).
  2. PC에서 http://127.0.0.1:8790/phone#remote를 열고 휴대폰 조작 화면을 켠 뒤 새 휴대폰 QR 만들기를 누릅니다.
  3. 앱에서 QR 코드 찍기를 누르고 PC 화면의 QR 코드를 찍습니다. 앱과 PC에 같은 확인 번호가 보이면 PC에서 승인합니다.
  4. 앱의 추적 시작을 누르고 휴대폰을 얼굴 정면 30에서 50cm 거리에 세워 둡니다.
  • 카메라 영상은 휴대폰 안에서만 처리하고 숫자 값만 보냅니다. 값마다 휴대폰에만 있는 비밀값으로 서명하며 PC는 승인한 휴대폰의 값만 사용합니다.
  • 거울처럼 움직이기, 위아래 반전, 정면 맞추기는 휴대폰 연결 화면의 휴대폰 얼굴 추적 설정을 따릅니다. 앱 값을 받는 중에는 웹캠 추적 창의 값을 쓰지 않습니다.
  • 추적 중에는 화면이 꺼지지 않습니다. 화면 어둡게로 배터리와 발열을 줄이고, 휴대폰이 뜨거우면 보내는 횟수를 자동으로 줄입니다.
  • 안드로이드 앱은 현재 시험용 서명이라 새 버전은 이전 앱을 지운 뒤 설치합니다.

앱의 카메라 영상 모드는 휴대폰 카메라 영상을 OBS로 직접 보냅니다(지연이 SRT보다 짧고 암호 입력이 필요 없음).

  1. OBS를 실행하고 http://127.0.0.1:8790/phone#camera의 앱 영상용 OBS 소스 만들기를 누르거나 debutkit camera setup --app을 실행합니다. 현재 방송 장면에 [DK] 휴대폰 카메라(앱) 브라우저 소스가 생깁니다(평소 투명).
  2. 앱에서 카메라 영상을 고르고 앞면이나 뒷면 카메라를 정한 뒤 보내기 시작을 누릅니다.
  • 영상은 휴대폰과 OBS 사이에서 직접 오가며 외부 서버를 거치지 않습니다. 소리는 보내지 않고 PC 마이크를 사용합니다.
  • OBS 소스를 다시 불러오거나 Wi-Fi가 잠시 끊기면 앱이 자동으로 다시 연결합니다. 공유기가 기기 사이 통신을 막는 경우(손님용 Wi-Fi 등)에는 연결되지 않습니다.

3D 캐릭터 동작

동작 파일을 등록하면 3D 캐릭터(VRM, GLB, FBX)가 대기 중 반복하는 기본 동작, 후원 반응, 수동 실행으로 움직입니다. 입 움직임과 얼굴 추적은 동작 위에 더해집니다.

파일구하는 곳비고
VRMA(VRM Animation)VRoid 공식 동작 7종(BOOTH, 무료) 등받은 zip을 그대로 등록. VRoid 공식 동작은 방송 화면이나 설명에 표기 필요, 파일 재배포 불가
FBXMixamo(무료, Adobe 계정)에서 동작을 고른 뒤 FBX로 받은 파일Skin은 With, Without 모두 가능. 걷기 등 이동 동작은 In Place 선택 권장. Mixamo 원본 파일 재배포 불가
GLBBlender 등에서 동작을 포함해 내보낸 파일파일 안에 동작이 여러 개면 등록할 때 하나를 선택
  1. 설정 마법사 캐릭터 단계의 3D 캐릭터 동작 카드에서 동작 파일 추가를 누릅니다. zip은 안의 동작 파일을 모두 등록합니다. 명령줄: debutkit motion add 파일
  2. 기본 동작에서 대기 중 반복할 동작을 고릅니다. 없음은 기본 움직임(호흡, 흔들림)입니다. 명령줄: debutkit motion idle 동작
  3. 후원 반응에 동작과 최소 금액을 지정한 뒤 오버레이를 시작합니다. 명령줄: debutkit overlay --motion-reaction 1000:동작
  4. 오버레이 실행 중에는 한 번 실행 버튼, 시작하기 화면의 동작 버튼, debutkit motion play 동작으로 바로 실행합니다.
  • FBX, GLB는 뼈 이름(Mixamo, VRoid, Unreal, Blender, MMD 등)으로 캐릭터의 뼈에 맞춰 변환합니다. 이동 거리는 캐릭터 키에 맞추고, A자 자세 캐릭터는 팔 방향을 보정합니다.
  • 동작에 든 입 모양, 눈 감기, 웃음 표정은 사용하지 않습니다. 목소리, 눈 깜빡임, 얼굴 추적이 우선합니다.
  • BVH 동작은 VRM 공식 변환 도구 bvh2vrma로 VRMA로 바꿔 등록합니다.
  • PNGTuber 캐릭터에는 동작이 적용되지 않습니다.

VTube Studio 연동(Live2D)

VTube Studio의 공개 API로 모델을 불러오고, 후원이 오면 VTube Studio 단축키(표정, 효과, 애니메이션)를 실행합니다.

  1. VTube Studio 설정에서 플러그인 API 사용을 켭니다(기본 포트 8001).
  2. 설정 마법사 캐릭터 단계의 VTube Studio 연결을 누르고, VTube Studio 화면에 나타나는 debutkit 플러그인 허용 요청을 수락합니다. 명령줄: debutkit vts login
  3. 모델, 단축키 불러오기로 목록을 받은 뒤 모델을 선택해 불러옵니다. 방송 프로그램으로 보내기로 넣은 새 모델은 VTube Studio를 다시 시작해야 목록에 표시됩니다.
  4. 후원 반응에 단축키 이름과 최소 금액을 지정하고 시험 실행으로 확인합니다. 오버레이를 시작하면 조건에 맞는 후원, 멤버십 알림 때 단축키가 실행됩니다.
  • 최소 금액은 원 기준이며 SOOP 별풍선은 1개 100원으로 계산합니다. Twitch 비트와 외화 후원은 최소 금액 0(모든 후원) 규칙에만 반응합니다.
  • 명령줄은 여러 규칙을 지정할 수 있습니다: debutkit overlay --vts-reaction 5000:Big --vts-reaction 1000:Heart(금액이 큰 규칙 우선)
  • VTube Studio 토큰은 이 PC의 설정 폴더(vts-token.json)에만 보관합니다. 삭제: debutkit vts logout

방송 로고 만들기

채널 이름과 심볼을 조합해 방송 로고(SVG, 투명 배경 PNG)를 만듭니다. 심볼은 함께 들어 있는 아이콘과 기본 도형(무료, 인터넷 연결 없음), 계정 없이 쓰는 공개 모델(AI Horde), 본인 PC나 계정의 공개 모델 Qwen-Image(ComfyUI 또는 Hugging Face 공개 데모) 또는 사용자 본인 API 키의 생성형 AI로 만듭니다.

  1. 설정 마법사의 채팅과 알림 단계에서 오버레이를 시작한 뒤 로고 만들기를 누릅니다. 브라우저에서 http://127.0.0.1:8790/logo를 열어도 됩니다.
  2. 채널 이름, 글꼴(Pretendard Bold, Black Han Sans), 배치(가로, 세로, 심볼만, 이름만), 글자 색과 배경색을 정합니다.
  3. 심볼은 아이콘(무료)에서 검색어(고양이, 마이크, 달, 하트, 케이크 등)나 분류로 찾아 고르거나, 기본 도형 8종에서 고르거나, AI로 만들기에서 서비스를 고르고 키를 저장(ComfyUI는 주소 입력, AI Horde는 키 없이 가능)한 뒤 설명, 느낌, 품질, 색을 정해 만들기를 누릅니다. 생성은 보통 30초에서 몇 분, AI Horde는 대기열 때문에 10분에서 30분 걸립니다.
  4. 심볼 마감에서 외곽선(보조 색), 굵은 외곽선, 스티커(외곽선과 흰 테두리), 흰 테두리를 고를 수 있습니다. 어떤 심볼에도 적용됩니다.
  5. 밝은 배경과 어두운 배경 미리보기를 확인하고 SVG 또는 PNG(512, 1024, 2048 픽셀)로 저장합니다.

아이콘

  • Microsoft Fluent Emoji(MIT)의 컬러 이모지(Flat) 356개와 단색 이모지(High Contrast), Phosphor Icons(MIT)의 선 아이콘 102개(굵기 6종)를 동물, 표정, 하트, 별과 하늘, 음악과 방송, 게임과 놀이, 음식과 디저트, 꽃과 자연, 판타지, 물건과 기호로 나눠 한국어 검색어와 함께 넣었습니다. 인터넷 연결 없이 동작합니다.
  • 컬러 이모지는 채널 색(가장 넓은 색을 주 색으로 바꾸고 다른 색은 밝기 차이를 유지한 같은 계열, 눈과 입 같은 어두운 색은 보조 색) 또는 원래 색으로 표시합니다. 단색 이모지와 선 아이콘은 주 색 한 가지로 칠합니다.
  • 선 아이콘 굵기는 글꼴에 맞춤을 고르면 Pretendard Bold에는 bold, Black Han Sans에는 fill을 씁니다.
  • 아이콘과 기본 도형은 다른 사용자도 같은 그림을 쓸 수 있는 비독점 재료라 상표로 독점하기 어렵습니다. 상표 등록이나 굿즈용 로고는 채널 이름 글자가 중심이 되게 만듭니다.
  • 아이콘 심볼이 들어간 SVG에는 AI 생성 표시 대신 세트, 아이콘 이름, 라이선스를 설명과 메타데이터로 넣고, 저장할 때마다 설정 폴더 logos의 made.jsonl에 채널 이름, 배치, 글꼴, 심볼 출처와 라이선스를 기록합니다. MIT 라이선스 전문은 설치 폴더 안 vendor/icons 폴더의 LICENSE-fluent-emoji.txt, LICENSE-phosphor.txt에 있습니다.

AI 심볼

  • AI Horde는 만들기를 누르면 바로 대기열에 올리고 화면에 대기열 위치, 남은 예상 시간, 경과 시간을 표시합니다. 로고 화면을 닫아도 debutkit이 켜져 있는 동안 계속 기다리고, 끝나면 최근 심볼에 추가합니다. 기다리기 취소를 누르면 AI Horde 대기열에서도 뺍니다.
  • AI Horde에 키 없이 보내는 설명에는 실명, 채널 이름, 연락처 같은 개인정보를 넣지 않습니다. 모델은 라이선스가 확인된 FLUX.1 schnell로 고정합니다.
  • ComfyUI 준비: ComfyUI를 설치하고 huggingface.co/Comfy-Org/Qwen-Image_ComfyUI의 split_files에서 diffusion_models(qwen_image_2512 또는 qwen_image의 fp8 파일), text_encoders(qwen_2.5_vl_7b_fp8_scaled), vae(qwen_image_vae) 파일을 ComfyUI의 같은 이름 models 폴더에 넣습니다. 빠름 품질에는 huggingface.co/lightx2v/Qwen-Image-Lightning의 8steps 파일을 loras 폴더에 함께 넣습니다(없으면 20단계로 실행). 그래픽 메모리가 부족하면 GGUF 모델(ComfyUI-GGUF)을 사용합니다.
  • 공개 모델(AI Horde, ComfyUI, Hugging Face)은 단색 배경 위에 그리게 한 그림을 이 PC에서 배경 제거, 가장자리 정리, 색 수 줄이기, 벡터화로 SVG 심볼로 만듭니다. 받은 원본 그림, 시드, 지시문은 설정 폴더의 logos에 보관합니다.
  • AI 심볼이 들어간 로고는 SVG 메타데이터에 AI 생성 표시(IPTC 디지털 소스 유형, 생성 서비스와 모델 이름)를 넣습니다. 방송 플랫폼과 앱 스토어의 AI 생성물 표시 규정을 확인합니다.
  • AI 생성물은 저작권 보호가 제한될 수 있습니다. 상표 등록이나 상업 사용 전에 KIPRIS에서 비슷한 상표를 확인합니다.
  • 설명에는 글자를 넣지 않고 그림만 묘사합니다. 다른 회사 로고나 캐릭터를 흉내 내는 설명은 사용하지 않습니다.
  • 받은 심볼은 정리(스크립트, 외부 주소, 내장 이미지 제거)한 뒤 사용합니다. 저장 전 미리보기에서 도형이 어긋난 곳이 없는지 확인합니다.
  • 어두운 배경용으로는 글자 색을 밝게 바꾼 로고를 따로 저장합니다.
  • 만든 심볼과 생성 기록은 설정 폴더의 logos에 보관합니다.

휴대폰 카메라 영상

휴대폰 카메라 영상(실사, 손 캠, 방 안 촬영)을 같은 Wi-Fi로 받아 OBS 소스로 표시합니다. OBS 기본 미디어 소스의 SRT 수신 기능을 사용하며 플러그인이 필요 없습니다. 송신 앱은 Larix Broadcaster(아이폰, 안드로이드 무료) 등 SRT 송신 앱을 사용합니다.

  1. OBS를 실행하고 설정 마법사 OBS 장면 단계의 휴대폰 카메라 소스 추가를 누르거나 debutkit camera setup을 실행합니다. 현재 방송 장면 왼쪽 위에 [DK] 휴대폰 카메라 소스가 생깁니다.
  2. 휴대폰과 PC를 같은 Wi-Fi에 연결하고, 표시된 QR 코드를 휴대폰 카메라로 찍어 Larix Broadcaster에 연결 정보를 가져옵니다. 오버레이 실행 중에는 http://127.0.0.1:8790/phone#camera에서도 QR 코드를 볼 수 있습니다.
  3. Larix의 방송 버튼(빨간 원)을 누르면 OBS에 영상이 표시됩니다. OBS가 처음 수신할 때 Windows 보안 경고가 나오면 개인 네트워크를 허용합니다.
  • 암호가 맞는 휴대폰만 연결됩니다(SRT 암호화, AES-128). 암호는 이 PC의 설정 폴더에만 보관하며 새 암호를 만들면 휴대폰 앱에 다시 등록합니다.
  • 소리는 보내지 않고 PC 마이크를 사용합니다. 다른 SRT 송신 앱은 주소(srt://PC주소:9710), 모드 Caller, 암호, 암호 길이 16을 직접 입력합니다.
  • 영상이 늦으면 5GHz Wi-Fi를 사용하고, 끊김이 잦으면 지연 여유를 늘립니다(기본 200밀리초).
debutkit camera setup                 # OBS 소스 만들기(있으면 포트, 암호 맞춤), 연결 정보 출력
debutkit camera setup --scene 토크     # 다른 장면에도 추가
debutkit camera info                  # 주소, 암호, Larix 가져오기 주소
debutkit camera status                # 휴대폰 연결 대기, 수신 중

시작하기 화면과 OBS에 넣기

오버레이를 켜면 열리는 시작하기 화면(http://127.0.0.1:8790) 맨 위에 방송 준비 목록이 있습니다. 진행 막대와 할 일 다섯 가지(debutkit 켜기, OBS 연결, 채팅창과 알림과 캐릭터를 OBS에 넣기, 시험 후원으로 확인, 방송 모양 고르기)를 차례로 보여 주며, OBS 연결과 OBS에 넣은 화면은 저절로 확인합니다. 다 끝나면 목록 접기로 접어 둡니다.

  1. OBS를 켜고 OBS 위 메뉴의 도구, WebSocket 서버 설정에서 WebSocket 서버 사용을 켭니다(OBS 28 이상에 들어 있음).
  2. 서버 비밀번호를 설정 마법사의 OBS 장면 단계에 넣고 오버레이를 켭니다. 화면 오른쪽 위에 OBS 연결됨과 지금 장면 이름이 보입니다.
  3. 방송 화면마다 있는 OBS에 넣기를 누릅니다. 지금 OBS 장면에 그 화면이 들어가고 이름([DK] 채팅 등), 크기, 자리가 맞춰집니다.
  • 후원 알림처럼 소리가 나는 화면은 OBS로 오디오 보내기와 오디오 모니터링(모니터와 출력)도 함께 맞춰 방송으로 소리가 나가고 내 헤드폰으로도 들립니다.
  • 이미 있는 화면은 주소(채팅창의 표시 형태 등)만 맞추며 장면에 이미 있으면 다시 넣지 않습니다. 설정 마법사의 장면 만들기로 만든 화면도 같은 이름을 씁니다.
  • OBS에 연결하지 못하면 할 일과 함께 끌어다 놓기 링크가 나옵니다. 링크를 OBS의 소스 목록으로 끌어다 놓으면 이름과 크기까지 맞춘 브라우저 소스가 생깁니다(OBS를 관리자 권한으로 실행했다면 되지 않음). 주소 복사로 직접 넣을 수도 있습니다.
  • 위쪽 메뉴는 시작하기, 꾸미기(방송 화면, 후원 알림), 방송 중 놀이(후원 추첨, 뽑기판, 후원 벽, 참여 레이스), 팬과 함께(팬 커뮤니티, 디스코드 합방), 더 보기(휴대폰, OBS 없이 방송, 로고 만들기, VMC 송신) 다섯 묶음이며 지금 묶음의 화면은 그 아래 줄에 나옵니다.
  • OBS, 장면, 브라우저 소스, WebSocket 같은 용어 옆의 ? 단추를 누르면 풀이가 나옵니다.
  • 방송 직전 점검: 방송 준비 목록 아래에서 방송할 때마다 다섯 가지를 확인합니다. OBS 연결, 지금 방송 장면에 채팅창과 알림이 있는지, 알림 소리가 방송과 내 헤드폰으로 나가는지(음소거, 모니터링), 채팅 연결(플랫폼별 연결됨과 받은 채팅 수, 끊김 이유, 데모 채팅만 있는지), 마이크(OBS 마이크 음량). 초록은 준비됨, 주황은 확인이 필요한 곳이며 장면에 없는 화면과 알림 소리는 단추로 바로 고칩니다.
  • 설정 마법사 마무리 단계의 다음 할 일에서도 시작하기 화면을 엽니다.

  2. 스타일(방송 스타일 따르기 또는 알림만 다른 스타일), 배치, 위치, 등장 움직임, 표시 시간, 크기를 고릅니다.
  3. 후원 문구와 구독 문구를 입력합니다. {name}은 후원자 이름, {amount}는 금액 자리입니다.
  4. 금액 구간을 추가하고 구간마다 그림, 강조 효과, 표시 시간, 효과음을 정합니다. 그림은 먼저 그림 올리기로 올립니다.
  5. 미리보기에서 작은 후원, 큰 후원, 별풍선, 구독 예시를 확인하고 저장합니다. 방송 화면으로 시험 알림은 OBS의 알림 소스에 시험 후원을 보냅니다.
  • 추천 모양 5가지(기본 카드, 크게 가운데, 아래 띠, 말풍선, 금액별로 다르게)를 누르면 배치, 위치, 움직임, 효과음, 금액 구간이 한꺼번에 채워집니다. 문구와 올린 그림은 그대로이며 처음 상태로는 기본값으로 돌립니다. 둘 다 저장해야 방송 화면에 반영됩니다.
  • 저장하지 않은 변경이 있으면 저장 단추에 바뀐 내용 있음이 붙고, 저장하지 않고 화면을 닫으려 하면 브라우저가 한 번 묻습니다.
  • 추천 모양과 배치 단추에는 그림 견본이 붙어 있습니다. 저장한 문구와 스타일로 그린 실제 알림 모습이며 소리 없이 이 화면에서만 그립니다.
  • 배치 6종: 카드, 가로 띠(화면 아래 한 줄), 말풍선, 큰 글자(바탕 없음), 그림 옆 글자, 그림 위 카드
  • 강조 효과 5종: 반짝이, 종이 조각, 흔들림, 빛 번짐, 크게. 큰 후원 구간에만 넣으면 금액에 따라 연출이 달라집니다.
  • 금액 구간은 원 기준이며 SOOP 별풍선은 1개 100원으로 계산합니다. Twitch 비트와 외화 후원은 최소 금액 0 구간을 씁니다.
  • 효과음 5종(차임, 동전, 팡파르, 퐁, 방울)은 브라우저에서 합성하며 OBS 브라우저 소스 속성의 OBS 오디오 제어를 켠 경우 방송에 나갑니다.
  • 올린 그림(PNG, GIF, WebP, JPEG, 8 MB 이하, 30개까지)은 이 PC의 설정 폴더 alert-images에만 보관합니다. 그림을 지우면 그 그림을 쓰던 구간은 그림 없이 표시합니다.

후원 추첨

후원이 오면 상품표에서 확률대로 뽑아 방송 화면에 카드 뒤집기, 룰렛, 캡슐 뽑기, 즉석 복권, 티켓 출력, 추첨기, 타로 중 고른 연출로 표시합니다. 평소에는 투명하고 추첨할 때만 화면 아래쪽에 나타납니다. 마스코트 마이(리본 마이크) 문양을 찍은 카드와 무대용 상품 룰렛, 후원자와 금액을 표시하는 하단 띠로 구성됩니다.

  1. 오버레이를 시작한 뒤 시작하기 화면의 후원 추첨 카드에서 추첨 설정과 시험 추첨을 엽니다. 설정 마법사에서는 채팅과 알림 단계의 후원 추첨 설정 버튼을 누릅니다.
  2. 상품표에 상품 이름과 가중치를 입력합니다. 가중치는 비율이며 확률이 바로 계산됩니다.
  3. 추첨 규칙에 최소 금액과 추첨 횟수를 입력합니다. 예: 1,000원 이상 1회, 10,000원 이상 11회
  4. 연출, 결과 표시 시간, 추첨 이름(예: 벌칙 룰렛), 표시 위치(아래 가운데, 왼쪽 아래, 오른쪽 아래), 크기를 정하고 후원이 오면 추첨(사용)을 체크한 뒤 저장합니다.
  5. 시험 추첨으로 방송 화면을 확인합니다. debutkit scenes로 만든 장면에는 후원 추첨 소스가 들어 있으며, 직접 추가할 때는 브라우저 소스 주소에 http://127.0.0.1:8790/draw를 입력합니다.
  • 금액은 원 기준이며 SOOP 별풍선은 1개 100원으로 계산합니다. Twitch 비트와 외화 후원은 최소 금액 0 규칙에만 반응합니다.
  • 규칙 적용 방식은 금액 이상이면 가장 큰 규칙(기본) 또는 금액이 정확히 같을 때만 중에서 고릅니다. 구독, 멤버십도 1회 추첨할 수 있습니다.
  • 확률 5% 이하 상품은 희귀 상품(금색), 이름에 꽝이 들어간 상품은 꽝(줄무늬), 나머지는 일반(핑크)으로 표시합니다.
  • 카드 연출 순서: 카드가 펼쳐진 뒤 희귀 카드만 금색 빛으로 미리 표시하고, 일반 카드를 먼저 뒤집은 다음 희귀 카드를 마지막에 천천히 뒤집습니다. 미리 표시는 실제 결과와 항상 같습니다.
  • 룰렛은 칸 경계의 못에 걸려 휘는 플래퍼와 테두리 전구로 돌아가며, 칸이 좁은 상품은 번호와 옆 범례로 표시합니다.
  • 효과음(선택)은 브라우저에서 합성하며 OBS 브라우저 소스 속성의 OBS 오디오 제어를 켠 경우 방송에 나갑니다. 확률 표시(선택)를 켜면 카드와 범례에 확률을 표시합니다.
  • 추첨은 이 PC의 debutkit이 운영체제 난수로 하며, 여러 화면이 같은 결과를 표시합니다. 여러 후원이 겹치면 하나씩 차례로 연출합니다.
  • 최근 결과에는 읽을 문장(대본)이 함께 표시되며 복사할 수 있습니다. 결과는 파일로 저장하지 않고 최근 100개만 메모리에 둡니다.
  • 미리보기: /draw?sample=card&count=11, /draw?sample=wheel은 저장한 설정으로 예시 추첨을 그 화면에서만 표시합니다. &bg=light는 밝은 배경 위 확인용입니다.
  • 글꼴은 함께 배포한 한글 글꼴(모두 SIL OFL)을 프로그램에 포함해 인터넷 연결 없이 표시합니다. 상품 이름과 안내 글은 공통 글꼴 목록에서 따로 고릅니다.
  • 소품 연출: 캡슐 뽑기(손잡이를 돌릴 때마다 등급 색 캡슐), 즉석 복권(동전으로 은박 긁기, 희귀 칸은 마지막에 천천히), 티켓 출력(등급 색 램프와 출력), 추첨기(구슬 색이 등급), 타로(카드를 섞어 한 장씩 펼치고 오늘의 한마디). 연출마다 모양 3종
  • 꾸미기: 결과 뒤 효과(종이 조각, 색 테이프, 불꽃놀이, 무대 조명, 하트, 별), 상품 이름과 안내 글의 글꼴과 크기. 타로의 한마디는 직접 입력하거나 기본 문장
  • 연출과 모양은 그림 단추로 고릅니다. 그림은 저장한 상품표로 뽑은 예시이며 소리 없이 이 화면에서만 움직입니다. 결과 뒤 효과, 글꼴, 타로 한마디, 추첨 이름, 위치와 크기는 자세히를 펼쳐 바꿉니다.
  • 추천 상품표 4가지(감사 인사, 벌칙 룰렛, 노래 신청, 꽝 없이)를 누르면 상품표가 채워집니다. 처음 상태로는 상품표, 규칙, 연출을 처음 값으로 채우며(사용 여부는 그대로) 둘 다 저장해야 반영됩니다. 저장하지 않은 변경은 저장 단추에 표시합니다.
  • 조작 화면의 대본 새 창(/draw/script)은 읽을 문장을 큰 글자로, 기록 화면(/draw/log)은 최근 결과와 상품별 합계를 보여 줍니다. 기다리는 추첨이 3개 이상이면 연출을 빠르게 합니다.

시청자 참여 추첨

채팅으로 참가자를 모은 뒤 당첨자를 뽑거나 참가자 순서를 정합니다. 결과는 후원 추첨과 같은 방송 화면(/draw)에 당첨 카드나 순서표로 표시합니다.

  1. 추첨 조작 화면의 시청자 참여 추첨에서 참가 명령(기본 !참가), 추첨 이름, 후원 참가 최소 금액(선택)을 정하고 모집 시작을 누릅니다. 지난 명단은 지워집니다.
  2. 모집 중에는 방송 화면 아래에 모집 띠(참가 명령, 참가 인원)와 새로 참가한 이름이 나타납니다. 채팅에 참가 명령을 입력한 시청자가 플랫폼과 닉네임 기준으로 1번씩 들어갑니다.
  3. 당첨 인원을 정하고 당첨자 뽑기를 누르거나, 순서 정하기를 누릅니다. 모집 중이면 자동으로 마감한 뒤 추첨합니다.
  • 후원 참가: 최소 금액 이상 후원한 시청자도 자동으로 참가합니다(원 기준, 별풍선 1개 100원). 0원은 모든 후원입니다.
  • 명단에서 시청자를 빼거나 이름을 직접 추가할 수 있습니다. 명단은 파일로 저장하지 않으며 최대 1,000명입니다.
  • 순서 정하기는 전체 순서를 섞고 방송 화면에는 앞에서 30명까지 표시합니다.
  • 미리보기: /draw?sample=raffle(당첨 카드), /draw?sample=order(순서표), /draw?sample=recruit(모집 띠)
  • 명령줄: debutkit raffle start --keyword !참가 --donation-min 5000, debutkit raffle status, debutkit raffle draw 3, debutkit raffle draw --order, debutkit raffle stop

휴대폰 조작 화면

같은 Wi-Fi의 휴대폰 브라우저로 시청자 참여 추첨(모집 시작, 마감, 당첨자 뽑기, 순서 정하기)과 3D 캐릭터 동작을 조작하고, 후원 추첨 최근 결과(읽을 문장)를 봅니다. 앱 설치는 필요 없습니다.

  1. 오버레이를 실행한 상태에서 설정 마법사의 휴대폰 조작 화면 버튼을 누르거나 http://127.0.0.1:8790/phone#remote를 엽니다.
  2. 이 PC 주소(공유기 주소, 보통 192.168로 시작)를 고르고 켜기를 누릅니다. 처음 켤 때 Windows 보안 경고가 나오면 개인 네트워크를 허용합니다.
  3. 새 휴대폰 QR 만들기를 누르고 휴대폰 카메라로 QR 코드를 찍어 조작 화면을 엽니다.
  4. 휴대폰과 PC의 등록 기기 목록에 같은 4자리 확인 번호가 보이면 PC에서 승인을 누릅니다. 이후에는 휴대폰에서 같은 주소를 열면 바로 사용합니다.
  • QR로 등록하고 PC에서 승인한 휴대폰만 조작할 수 있습니다. QR이 방송 화면에 노출되어도 승인하지 않으면 조작할 수 없으며, QR은 5분 동안 1대만 등록합니다.
  • 요청마다 휴대폰에만 있는 비밀값으로 서명합니다. 비밀값은 QR 코드로만 전달되고 네트워크로 오가지 않습니다. 화면 내용은 암호화하지 않으므로 같은 Wi-Fi의 다른 기기가 볼 수는 있으나 조작할 수는 없습니다.
  • 뽑기와 순서 정하기는 실수를 막기 위해 다시 눌러야 실행됩니다. 등록 기기는 최대 5대이며 PC에서 삭제하면 즉시 차단됩니다.
  • PC 주소가 바뀌면(공유기 변경 등) 조작 화면을 다시 켜고 휴대폰을 다시 등록합니다.
debutkit remote start --address 192.168.0.5   # 켜기(기본 포트 8792)
debutkit remote pair                          # 새 휴대폰 등록 주소(5분 유효)
debutkit remote status                        # 등록 기기와 확인 번호
debutkit remote approve 기기                   # 승인(remove로 삭제)

방송 연출(뽑기판, 후원 벽, 참여 레이스)

뽑기판, 후원 벽, 참여 레이스는 오버레이와 함께 실행되는 방송 화면입니다. debutkit scenes로 만든 본방송과 토크 장면에 숨긴 채로 들어 있으므로 쓸 때 OBS 소스 목록의 눈 아이콘으로 켭니다. 조작 화면은 OBS 독(사용자 지정 브라우저 독)으로도 씁니다. 모든 조작 화면 위의 이동 막대로 화면 사이를 오갑니다.

방송 화면 미리보기, 방송 색, 방송 스타일

  • http://127.0.0.1:8790/stage는 채팅, 캐릭터, 알림, 추첨, 후원 벽, 목표 게이지, 순위, 뽑기판, 레이스를 OBS 장면과 같은 자리에 겹쳐 보여 줍니다. 시험 후원(단위와 금액), 시험 채팅, 구독으로 후원 하나가 여러 화면에 어떻게 나오는지 확인합니다.

게임 패키지와 프레임

  • 게임 패키지 = 그 게임 느낌의 방송 스타일 + 색 + HUD를 피한 배치 + 프레임과 대기 화면 배경
  • 10종: 발로란트, 리그 오브 레전드, 오버워치, 하스스톤, 배틀그라운드, 메이플스토리, 로스트아크, FC 온라인, 전략적 팀 전투, 마인크래프트
  1. 방송 화면 미리보기를 열고 게임 패키지에서 게임 고르기
  2. 오른쪽 미리보기 확인: 그 게임 배경 그림, 게임 모양의 알림, 채팅, 캐릭터 프레임(적용 전까지 저장 안 함)
  3. 적용할 항목 고르기: 방송 스타일과 색, 알림 위치, 장면 배치와 프레임
  4. 패키지 적용 누르기(스타일과 알림 위치는 OBS에 바로 반영)
  5. OBS 장면 배치: 설정 마법사 OBS 장면 단계의 게임 배치, 또는 debutkit scenes --game lol --replace
  6. 프레임 문구 입력: 이름표, 대기, 자리 비움, 엔딩, 아래 한 줄(방송 일정, SNS), 대기 시간
  7. 대기, 자리 비움, 엔딩 화면 그림 고르기(선택)
    • 데비: 기본 3D 캐릭터가 대기 화면에서 손 인사, 자리 비움에서 조는 모습, 엔딩에서 만세
    • 방송 캐릭터 그림: 방송에 쓰는 캐릭터(PNGTuber는 입 다문 그림, 3D는 미리보기 그림)
    • 그림이 있으면 문구는 왼쪽, 그림은 오른쪽. OBS 주소에 &art=debi를 붙이면 그 화면만 다르게
  • 게임별 모양
    • 발로란트: 짙은 남색 판, 붉은 막대, 비스듬히 자른 모서리, 좁은 대문자
    • 리그 오브 레전드, 전략적 팀 전투: 금빛 이중 테두리, 마름모와 육각 장식, 고전 세리프
    • 오버워치: 흰 판, 주황 사선, 기울인 굵은 글자
    • 하스스톤: 양피지 카드, 나무 테두리, 파란 보석
    • 배틀그라운드: 올리브 판, 노란 막대, 경고 줄무늬
    • 메이플스토리: 흰 둥근 창, 주황 머리띠, 말풍선 채팅
    • 로스트아크: 푸른 검정 판, 금빛 L자 모서리
    • FC 온라인: 중계 점수판처럼 검정 판에 잔디 초록 막대
    • 마인크래프트: 업적 알림 같은 베벨 판, 도트 글자
  • 대기, 자리 비움, 엔딩 화면: 그 게임 느낌의 배경 그림 위에 문구
  • 게임 배치의 채팅창: 게임 스타일 카드(/chat?theme=style)
  • HUD 자리: 기본 HUD 설정 기준. 게임에서 HUD를 옮겼다면 OBS에서 소스도 옮기기
  • 장르 스타일 8종(택티컬, 마법 금장 등): 목록에 없는 게임은 방송 스타일에서 따로 고르기
  • 글자: 영문과 숫자는 Windows 기본 글꼴(Bahnschrift, Palatino), 한글은 함께 배포한 글꼴과 바탕. 메이플스토리체를 설치했다면 메이플스토리 패키지에 씀
  • 프레임 주소: /frame?kind=cam(캐릭터와 캠 테두리, 이름표), screen(게임 화면 테두리), starting(대기, 카운트다운), brb(자리 비움), ending(엔딩). &look=neon은 그 화면만 다른 스타일, &name=은 이름표, &minutes=5는 대기 시간입니다.

  • 장식: debutkit에서 그린 도형. 게임 회사의 로고, 공식 글꼴, 캐릭터와 그림, 게임 효과음 없음
  • 팬이 만든 꾸미기이며 게임 회사와 관계없음. 게임 이름은 각 회사의 상표

뽑기판

  1. http://127.0.0.1:8790/pick/control에서 제목, 칸 수, 상품과 수량을 입력하고 저장합니다. 상품을 채우고 남은 칸은 꽝(이름 변경 가능)입니다.
  2. 칸을 누르면 방송 화면에서 같은 칸이 열리고 결과 카드가 나옵니다. 번호를 비우고 무작위로 열기도 됩니다.
  3. 배치 보기(이 화면에만)로 당첨 칸 위치를 확인할 수 있습니다. 방송 화면에는 연 칸만 전달합니다.
  • 디자인과 덮개 무늬는 그림 단추로 고릅니다. 그림은 저장한 색과 글꼴로 그린 12칸 예시 판(3번 당첨, 8번 꽝이 열린 모습)입니다. 처음 상태로는 디자인, 글자, 연출과 소리, 방송 화면 표시를 처음 값으로 채우고 판과 상품, 시청자 참여는 그대로 둡니다(저장해야 반영).
  • 디자인 7종(카드 뒤집기, 긁는 복권, 봉투, 캡슐, 작은 문, 스티커 떼기, 메모지), 색(첫 항목은 방송 색), 칸 덮개 11종, 글꼴, 열기 효과 10종과 꽝 효과, 당첨과 꽝 효과음, 제목, 설명, 결과 카드의 글자 크기와 색과 정렬
  • 시청자 참여(선택): 채팅 명령(기본 !뽑기 7)이나 정한 금액 이상의 후원으로 칸 열기. 열 수 있는 사람(모두, 후원자만, 스트리머와 매니저만), 시청자별 대기 시간, 플랫폼 선택
  • 공정성 확인: 판을 만들 때 배치와 무작위 문자열로 만든 SHA-256 값을 방송 화면 아래에 공개합니다. 끝내고 배치 공개를 누르면 배치와 문자열을 공개해 누구나 같은 값인지 확인할 수 있습니다.
  • 되돌리기(마지막으로 연 칸), 남은 칸 섞기, 처음부터, 여러 판 저장과 전환, 열기 기록과 대본 복사, 방송 표시와 숨기기. 판 상태는 설정 폴더의 pick.json에 저장해 다시 실행해도 이어집니다.
  • 명령줄: debutkit pick status, pick open 7 --by 이름, pick undo, pick reshuffle, pick finish, pick hide

후원 벽, 목표 게이지, 후원 순위

들어온 후원을 단위별 칸에 카드로 쌓아 방송 화면에 벽지처럼 둡니다. 치지직 치즈, SOOP 별풍선과 애드벌룬, YouTube 슈퍼챗, Twitch 비트를 함께 받습니다. 조작 화면은 http://127.0.0.1:8790/wall/control입니다.

  • 칸 묶기: 단위마다 정확한 개수, 앞자리별(30~39개), 자릿수별, 10, 100, 1000 단위(원은 천과 만 단위). 시그니처 금액은 올린 그림(PNG, GIF, WebP, JPEG, 8 MB 이하)으로 따로 크게 세우고 그림 안에 숫자가 있으면 숫자를 숨깁니다.
  • 오라 단계(많이 보낼수록 빛 번짐, 반사광, 별가루, 금박), 등장 연출 10종, 대기 효과 6종. 몰려도 차례대로 붙고 기다리는 카드가 많으면 빠르게 붙습니다.
  • 연출 칸의 그림은 예시 카드에 고른 등장과 대기 효과를 붙인 모습이며 마지막 카드의 등장을 되풀이합니다. 추천 연출 4가지(차분하게, 귀엽게, 화려하게, 매번 다르게)와 처음 상태로가 있고, 빠른 진행과 시작할 때 비우기 같은 설정은 자세히에 접혀 있습니다. 저장하지 않은 칸은 저장 단추에 표시합니다.
  • 배치: 자동 배치는 오른쪽 채팅 자리를 비웁니다(선택). OBS의 상호 작용 창이나 조작 화면 미리보기에서 칸을 끌어 옮기고 크기를 바꿉니다. 장면 만들기는 후원 벽을 캐릭터 뒤에 둡니다.
  • 목표 게이지(/wall/goal, 권장 1280x240)는 원 기준 합계나 단위별 개수와 중간 목표, 후원 순위(/wall/rank, 권장 560x720)는 원 기준 순위입니다. 장면 만들기는 둘 다 왼쪽 위에 작게 숨겨 넣습니다.
  • 시험 카드(시험 표시, 시험 카드 지우기로 정리), 카드 떼어 옮기기, 마지막 카드 다시 보기, 비우기와 8초 안에 되돌리기, 후원자별 합계 내보내기
  • 후원자 닉네임과 금액은 이 PC의 설정 폴더 wall.json에만 저장하고 외부로 보내지 않습니다. 방송 화면에서 닉네임 숨기기, 오버레이를 시작할 때 비우기를 고를 수 있습니다.
  • 명령줄: debutkit wall status, wall test --unit 별풍선 --amount 100, wall clear, wall undo, wall clear-tests, wall export --out 기록.txt

참여 레이스

시청자 참여 추첨의 참가자(채팅 !참가, 후원 참가, 직접 추가)가 방송 화면에서 겨룹니다. 조작 화면은 http://127.0.0.1:8790/race/control입니다.

  • 게임: 구슬 레이스(코스 3종), 달리기 경주(8명씩 예선과 결승 또는 30명까지 같이), 서바이벌(좁아지는 경기장에서 끝까지 남기). 붙여 넣은 이름도 참가하며 이름*3은 3번 참가합니다. 한 판 최대 100명
  • 순위와 시드는 시작할 때 debutkit이 운영체제 난수로 정해 방송 화면과 조작 화면이 같은 결과를 보여 줍니다. 경기 중에 연 화면도 지금 장면부터 이어서 보여 줍니다. 화면 아래에 시드 번호를 표시합니다.
  • 깜짝 요소(없음, 조금, 많이와 종류별 켜기), 당첨 순위(1등, 꼴등, 직접 입력), 경기 길이, 재생 속도 0.7~2.2배, 디자인 3종, 색(첫 항목은 방송 색), 글꼴, 효과음
  • 게임, 코스, 디자인은 그림 단추로 고릅니다. 그림은 저장한 설정의 예시 경주를 중간에 멈춘 장면입니다. 추천 3가지(가볍게 한 판, 빠른 달리기, 끝까지 긴장)와 처음 상태로(게임과 꾸미기만, 참가자 설정은 그대로)가 있으며 이 화면은 바꾸면 바로 저장합니다. 재생 속도와 깜짝 요소는 자세히에 접혀 있습니다.
  • 결과는 채팅창 안내 한 줄로 알리고 전체 순위와 조별 기록을 텍스트 파일로 저장할 수 있습니다. 연습 모드는 예시 이름으로 미리 해 봅니다.
  • 명령줄: debutkit race start --game marble, race start --names "치즈냥*3, 도토리", race next, race stop, race status

팬 커뮤니티

트게더처럼 내 팬들이 모이는 커뮤니티를 만듭니다. 공지, 방송 일정, 자유, 팬아트, 질문, 클립 게시판과 댓글, 추천, 출석과 포인트, 등급, 순위가 있고 debutkit이 방송 중 채팅, 참여 추첨, 방송 화면과 이어 줍니다. 커뮤니티는 스트리머 본인의 Cloudflare 무료 계정에 올라가 PC를 꺼도 열려 있으며, debutkit 팀은 서버를 운영하지 않습니다.

만들기

  1. Cloudflare 무료 계정을 만듭니다. 카드 등록은 필요 없습니다.
  2. Cloudflare 대시보드의 내 프로필, API 토큰에서 토큰 만들기를 누르고 "Cloudflare Workers 편집" 템플릿을 고른 뒤 권한에 계정 D1 편집을 더해 만듭니다.
  3. 오버레이를 실행한 상태에서 http://127.0.0.1:8790/community/control(이동 막대의 커뮤니티)을 열고 커뮤니티 이름, 주소 이름(예: dotori-fans), 스트리머 이름, API 토큰을 넣고 올리기를 누릅니다.
  4. 커뮤니티 주소(https://주소이름.계정이름.workers.dev)가 나오면 관리 화면 열기로 스트리머로 로그인해 이용 규칙, 소개, 개인정보 담당 연락처를 정합니다.
  • 토큰은 이 PC에만 암호화해 보관합니다(Windows DPAPI). 같은 주소 이름으로 다시 올리면 글과 회원은 그대로 두고 커뮤니티 프로그램과 설정만 고칩니다.
  • 무료 한도: 하루 요청 10만 번, 데이터베이스 5 GB, 그림 저장 1 GB(그림 하나 3 MB 이하). 처음 시작하는 채널에는 충분하며 넘으면 그날은 잠시 멈춥니다.
  • 명령줄: debutkit community deploy --script dotori-fans --name "도토리네 쉼터"(토큰은 CLOUDFLARE_API_TOKEN), community status, community notice 제목 --pin, community admin, community live on
  • 올리기 전에 화면만 보려면 debutkit community preview(Node.js 22.5 이상, 시험용 데이터, 이 PC에서만)를 씁니다.

시청자 가입과 로그인

  • 방송 채팅 인증(설정 필요 없음): 커뮤니티의 로그인에서 이용 규칙과 개인정보 처리방침에 동의하고 만 14세 이상을 확인하면 숫자 6자리가 나옵니다. 방송 중 채팅에 !인증 숫자를 입력하면 debutkit이 채팅을 보고 그 채팅 계정(치지직, SOOP, YouTube, Twitch)으로 가입시킵니다. 이메일과 비밀번호가 없습니다.
  • 채팅의 스트리머와 매니저는 커뮤니티에서도 스트리머, 매니저 권한을 받습니다. 닉네임을 바꿔도 플랫폼의 계정 번호로 같은 사람을 알아봅니다.
  • 방송이 없을 때도 가입받으려면 치지직, 디스코드, 구글 로그인을 켭니다. 서비스별 개발자 화면에서 앱을 만들고 Client ID와 Secret을 커뮤니티 화면의 플랫폼 로그인에 넣은 뒤 다시 올리고, 화면에 나온 돌아올 주소를 앱에 등록합니다. 네이버, 카카오 로그인은 서비스 검수가 필요해 넣지 않았습니다.
  • 로그인한 시청자는 내 정보에서 다른 채팅 계정을 더 연결할 수 있습니다. 이미 다른 회원에 연결된 계정은 연결하지 않습니다.

방송 연동

  • 채팅 !출석: 커뮤니티에 연결한 시청자에게 하루 한 번 포인트를 주고 방송 화면에 출석 카드를 띄웁니다. 커뮤니티의 출석 체크는 따로 하루 한 번이며 연속 출석은 점수를 더 줍니다.
  • 방송 중 표시: 실제 플랫폼 채팅이나 후원이 처음 오면 커뮤니티 맨 위에 방송 중 표시(방송 주소 링크)를 켜고 오버레이를 멈추면 끕니다. 커뮤니티 화면의 단추로 직접 켜고 끌 수도 있습니다.
  • 방송에 띄우기: 스트리머나 매니저가 커뮤니티 글의 방송에 띄우기를 누르면 OBS 브라우저 소스 http://127.0.0.1:8790/community(권장 크기 1920x1080)에 글과 팬아트가 방송 스타일 카드로 차례로 나옵니다.
  • 참여 추첨: 추첨 조작 화면에서 모집을 시작하면 커뮤니티에도 참가 단추가 나오고 커뮤니티 참가자가 명단에 더해집니다.
  • 공지와 방송 일정은 커뮤니티 화면에서 올립니다. 일정은 매주 일정과 그날만 일정(특별 방송, 휴방)을 함께 올리며 커뮤니티 홈에 이번 주 방송으로 나옵니다.
  • 방송 화면 미리보기의 시험 채팅으로 !인증, !출석을 방송 없이 시험할 수 있습니다(시험 계정으로 들어감).

운영과 개인정보

  • 커뮤니티의 운영자는 스트리머입니다. 개인정보 처리방침(수집 항목, 국외 이전, 탈퇴와 삭제)과 기본 이용 규칙이 자동으로 들어가며 관리 화면에서 이용 규칙과 연락처를 바꿉니다.
  • 받는 정보는 플랫폼 계정 번호, 닉네임, 프로필 그림 주소, 쓴 글과 포인트 기록뿐이며 이메일, 실명, 전화번호는 받지 않습니다. 만 14세 미만은 가입하지 않도록 확인합니다.
  • 신고된 글과 댓글은 관리 화면에 모이며 가리기(임시 조치)나 문제 없음으로 처리합니다. 가려진 글의 작성자에게는 임시 조치 안내가 보입니다. 권리 침해 신고(명예훼손, 사생활 침해)는 정보통신망법에 따라 지체 없이 가리고 알립니다. 불법촬영물은 알게 되는 즉시 지웁니다.
  • 매니저는 신고 처리, 가리기, 고정, 방송에 띄우기, 정지를 하고 매니저 지정과 커뮤니티 설정은 스트리머만 합니다.
  • 포인트는 활동 기록이며 사고팔거나 다른 사람에게 줄 수 없고 현금 가치가 없습니다.
  • 관리 화면의 데이터 내보내기로 회원, 글, 댓글, 일정, 포인트를 JSON 파일로 받습니다. 커뮤니티를 옮기거나 닫기 전에 받아 둡니다. 닫을 때는 Cloudflare 대시보드에서 Worker, D1, KV를 지웁니다.

디스코드 합방

여러 스트리머가 디스코드 음성으로 대화하며 함께 방송할 때 쓰는 기능입니다. 오버레이를 켜고 위쪽 메뉴의 팬과 함께, 디스코드 합방(http://127.0.0.1:8790/discord/control)을 엽니다.

합방 참여자 화면

  1. StreamKit을 열고 OBS용 설치를 눌러 디스코드에서 허락합니다.
  2. 음성 위젯에서 서버와 음성 채널을 고르고 오른쪽의 주소를 복사해 음성 위젯 주소에 붙여 넣습니다.
  3. 배치(세로, 가로), 그림 크기, 이름 보이기, 이름표를 방송 스타일로, 말하는 사람만 밝게를 고르고 OBS에 넣기를 누릅니다.
  • 디스코드 공식 음성 위젯(StreamKit)을 쓰므로 이 PC의 디스코드 앱이 켜져 있어야 합니다. debutkit은 디스코드에 접속하지 않고 위젯의 모양(OBS 사용자 지정 CSS)만 만듭니다.
  • 참여자 그림: 참여자의 디스코드 사용자 ID(디스코드 설정의 고급에서 개발자 모드를 켜고 이름을 오른쪽 클릭, 사용자 ID 복사)와 평소 그림, 말할 때 그림(각 400 KB 이하)을 넣으면 프로필 사진 대신 캐릭터 그림이 나오고 말할 때 바뀝니다. 그림을 쓰기 전에 참여자에게 먼저 물어봅니다. 기본 프로필 사진을 쓰는 사람은 바꿀 수 없습니다.
  • 미리보기는 예시 참여자 세 명으로 보여 줍니다. 디스코드가 위젯 모양을 바꾸면 꾸미기가 맞지 않을 수 있습니다.

디스코드 방송 알림

  1. 디스코드에서 알림을 올릴 채널의 설정(톱니바퀴), 연동, 웹후크, 새 웹후크를 누르고 웹후크 URL을 복사합니다.
  2. 디스코드 합방 화면의 방송 알림에 붙여 넣고 저장한 뒤 시험 보내기를 누릅니다.
  3. 채널 이름, 방송 주소, 시작 알림 글과 끝 알림 글을 정합니다.
  • 방송 시작 알림은 실제 방송 채팅이나 후원이 처음 올 때(시험 채팅과 데모 채팅은 제외), 방송 끝 요약(채팅 수, 후원 수, 원으로 바꾼 합계)은 오버레이를 멈출 때 보냅니다. 지금 보낼 글로 직접 알림도 보냅니다.
  • @everyone 같은 호출은 보내지 않습니다. 웹후크 주소는 이 PC에 암호화해 보관하며 방송 화면과 기록에 남기지 않습니다.

OBS 없이 바로 방송

캐릭터, 채팅, 후원 알림, 추첨 연출을 한 화면에 모은 송출 화면을 OBS 없이 치지직, SOOP, YouTube, Twitch로 바로 보냅니다. 송출 화면 창(Edge 앱 창)을 ffmpeg로 캡처해 하드웨어 H.264와 마이크 소리로 송출합니다. 게임 화면 캡처와 장면 전환은 없으므로 게임 방송은 OBS를 사용합니다. 현재 Windows 10(1903 이상), Windows 11을 지원합니다.

준비

  1. ffmpeg를 준비합니다(debutkit setup --ffmpeg 또는 설정 마법사의 ffmpeg 다운로드 버튼).
  2. 오버레이를 실행한 상태에서 설정 마법사의 OBS 없이 바로 방송 버튼을 누르거나 http://127.0.0.1:8790/broadcast/control을 엽니다.
  3. 방송 플랫폼을 고르고 스트림 키를 붙여 넣은 뒤 키 저장을 누릅니다. 치지직과 SOOP은 방송 설정 화면의 송출 서버 주소(rtmp://로 시작)도 붙여 넣습니다. YouTube와 Twitch는 기본 주소를 사용합니다.
  4. 마이크를 고르고 송출 화면 열기로 화면을 확인한 뒤 방송 시작을 누릅니다.

사용 시 확인 사항

  • 송출 화면 창이 곧 방송 화면입니다. 다른 창에 가려져도 되지만 최소화하면 방송 화면이 멈추고, 다시 띄우면 이어서 송출합니다. 방송 중 창을 닫으면 약 10초 뒤 방송이 끝납니다. 창을 작게 줄이면 화질이 떨어집니다.
  • 화질은 720p 30fps를 권장합니다. 인코더는 NVIDIA, Intel, AMD 그래픽의 하드웨어 인코더 중 이 PC에서 되는 것을 자동으로 고르고, 없으면 CPU(x264)를 사용합니다. PC가 따라가지 못하면 조작 화면에 경고가 표시됩니다.
  • 후원 알림 효과음과 음악도 보낼 때는 Windows 소리 설정에서 스테레오 믹스를 켜고 함께 보낼 소리 장치로 선택합니다.
  • 방송한 지 20초가 지난 뒤 연결이 끊기면 자동으로 다시 연결합니다. 시작하자마자 끝나면 조작 화면에 이유(서버 주소, 스트림 키 등)가 표시됩니다.
  • 창 캡처에는 그래픽 장치(D3D11)가 필요합니다. 그래픽 드라이버가 없는 가상 머신 등에서는 안내 문장이 표시되며 OBS를 사용합니다.
  • 스트림 키가 알려지면 다른 사람이 내 채널로 방송할 수 있습니다. 키를 방송 화면에 띄우지 말고, 노출되었다면 방송 플랫폼에서 키를 다시 발급합니다.
debutkit broadcast set --platform chzzk --server rtmp://(치지직 스트림 URL)
debutkit broadcast key        # 스트림 키 입력(화면에 표시하지 않음)
debutkit broadcast devices    # 녹음 장치와 인코더
debutkit broadcast set --mic "마이크 이름" --quality 720p30
debutkit broadcast start      # 방송 시작(stop으로 끝내기)

휴대폰만으로 바로 방송(안드로이드)

debutkit 휴대폰 앱의 바로 방송 탭은 PC 없이 휴대폰에서 바로 송출합니다. 캐릭터 화면(debutkit 기본 캐릭터 또는 고른 그림 두 장이 마이크 소리에 맞춰 입을 움직임) 또는 카메라 영상과 마이크 소리를 보냅니다.

  1. 앱의 바로 방송 탭에서 방송 플랫폼을 고르고 스트림 키를 붙여 넣은 뒤 키 저장을 누릅니다. 치지직과 SOOP은 방송 설정 화면의 송출 서버 주소도 붙여 넣습니다.
  2. 방송 화면에서 캐릭터 화면이나 카메라 영상을 고릅니다. 캐릭터 화면은 배경색, 왼쪽 위 글자, 캐릭터 그림(입 닫은 그림과 입 연 그림, 투명 배경 PNG 권장), 입 움직임 민감도를 정합니다. 카메라 영상은 휴대폰을 가로로 들고 방송합니다.
  3. 화질을 고르고 방송 시작을 누릅니다. 처음에는 마이크(카메라 영상이면 카메라)와 알림 사용을 허용합니다.
  • 방송 중에는 화면이 꺼지지 않으며, 다른 앱으로 바꾸거나 화면을 꺼도 송출은 이어집니다. 알림의 방송 끝내기로 멈춥니다.
  • 모바일 데이터로 방송하면 720p 기준 1시간에 약 1.2 GB를 사용합니다. 연결이 느리면 비트레이트를 자동으로 낮추고, 방송 중 연결이 끊기면 5초 뒤 다시 연결합니다.
  • 휴대폰이 뜨거우면 영상 비트레이트를 낮춥니다. 장시간 방송은 충전기를 빼고 케이스를 벗긴 상태를 권장합니다.
  • 채팅과 후원 알림 표시는 아직 없습니다. 아이폰 앱의 바로 방송은 다음 버전 이후입니다.

자동 클립

준비

  1. ffmpeg를 준비합니다. Windows는 debutkit setup --ffmpeg 또는 설정 마법사의 ffmpeg 다운로드 버튼(약 115 MB, SHA-256 검증), macOS는 brew install ffmpeg, Linux는 배포판 패키지 관리자를 사용합니다.
  2. debutkit scenes --replay-buffer로 OBS 리플레이 버퍼를 설정하고 OBS를 재시작합니다.
  3. 오버레이와 함께 실행합니다: debutkit overlay --chzzk-api --clip

저장 기준

채팅 급증방송별 평소 채팅량보다 크게 증가한 시점. 시청자가 적은 방송에도 적용
표시 명령스트리머, 매니저의 !clip, !클립 입력. 시청자의 입력은 무시
동시 송출모든 플랫폼 채팅을 합산해 판단. YouTube 채팅은 요청 간격 때문에 최대 10초 늦게 반영
저장 위치동영상/debutkit-clips. --clip-dir로 변경
결과 표시시작하기 화면의 채팅창 미리보기와 설정 마법사의 기록 영역

방송 없이 시험하려면 시작하기 화면의 스트리머 !clip 버튼을 사용합니다.

클립 길이

  • 리플레이 버퍼 최대 시간보다 긴 클립은 버퍼 길이로 저장되며 안내가 표시됩니다.
  • OBS 설정의 출력 탭에서 리플레이 버퍼 최대 시간을 늘리거나 scenes --replay-buffer 120으로 다시 설정합니다.

움짤과 세로 쇼츠

저장한 클립이나 다른 영상으로 움짤(GIF, WebP)과 세로 쇼츠(1080x1920 MP4, 소리 포함)를 만듭니다. 결과는 원본 옆에 저장하고, 같은 이름이 있으면 번호를 붙여 덮어쓰지 않습니다.

  • 자동 클립과 함께: 설정 마법사의 클립마다 움짤(GIF), 클립마다 세로 쇼츠를 선택하거나 debutkit overlay --clip --clip-gif --clip-shorts. 움짤은 클립 앞 6초, 폭 480
  • 직접 만들기: debutkit clip gif 클립.mp4 --start 3 --duration 5, debutkit clip webp 클립.mp4(Pillow 필요), debutkit clip shorts 클립.mp4 --mode crop --focus 0.8
  • 쇼츠 형태: blur 흐린 배경 위에 원본(기본), crop 세로로 자르기(--focus 0은 왼쪽, 1은 오른쪽. 캐릭터가 있는 쪽), fit 위아래 여백
  • 워터마크: --watermark 로고.png --watermark-position bottom-right --watermark-size 18 --watermark-opacity 85. 방송 로고 만들기의 투명 PNG를 그대로 사용

치지직 공식 API

본인 채널의 채팅, 후원, 구독을 네이버 공식 Open API로 수신합니다. 비공식 수신보다 안정적이며 후원 정보가 정확합니다.

애플리케이션 등록

  1. 치지직 개발자 센터에서 애플리케이션을 등록합니다.
  2. 로그인 리디렉션 주소에 http://localhost:8765/callback을 등록합니다.
  3. API 사용 범위에서 채팅, 후원, 구독 관련 항목을 선택합니다.
  4. Client ID와 Client Secret을 확인합니다.

로그인

설정 마법사에서는 채팅과 알림 단계의 치지직 API 입력란에 Client ID와 Client Secret을 입력한 뒤 치지직 로그인 버튼을 누릅니다. 명령줄에서는 다음과 같이 실행합니다.

$env:CHZZK_CLIENT_ID = "Client ID"
$env:CHZZK_CLIENT_SECRET = "Client Secret"
debutkit chzzk login
debutkit overlay --chzzk-api
  • 브라우저에서 동의하면 토큰이 발급되어 이 PC의 사용자 설정 폴더에 보관되며, 만료 시 자동으로 갱신됩니다.
  • Client ID와 Client Secret은 토큰 갱신에 사용되므로 실행할 때마다 환경 변수 또는 입력란에 지정해야 합니다. 파일에는 저장하지 않습니다.
  • 로그아웃(토큰 삭제): debutkit chzzk logout

YouTube 채팅

YouTube 방송의 채팅, 슈퍼챗, 슈퍼스티커, 멤버십 정보를 공식 YouTube Data API로 수신합니다. Google Cloud에서 발급한 API 키가 필요합니다.

API 키 발급

  1. Google Cloud 콘솔에서 프로젝트를 생성합니다.
  2. API 라이브러리에서 YouTube Data API v3를 사용 설정합니다.
  3. 사용자 인증 정보에서 API 키를 만듭니다. API 제한은 YouTube Data API v3로 설정할 것을 권장합니다.

실행

설정 마법사에서는 채팅과 알림 단계의 YouTube 입력란에 방송 주소와 API 키를 입력합니다. 명령줄에서는 다음과 같이 실행합니다.

debutkit overlay --youtube https://www.youtube.com/watch?v=영상ID --youtube-key API키
debutkit overlay --youtube 영상ID --youtube-interval 15
  • 방송 주소는 방송마다 바뀌는 영상 주소를 사용합니다. 채널 주소는 지원하지 않습니다.
  • API 키는 --youtube-key 또는 환경 변수 YOUTUBE_API_KEY로 지정하며, 요청 머리글로만 전송하고 저장하지 않습니다.
  • 연결 직후의 지난 채팅은 표시하지 않고, 그 이후 채팅부터 표시합니다.

연결 확인

방송 전에 API 키와 수신 방식을 확인합니다. 방송 중인 영상 주소가 필요하며 할당량 약 11 단위를 사용합니다. 설정 마법사에서는 YouTube 입력란 옆의 연결 확인 버튼을 사용합니다.

debutkit youtube check https://www.youtube.com/watch?v=영상ID --youtube-key API키

방송 주소영상 ID 해석없음
API 키, 라이브 채팅API 키 유효 여부, 방송 중인 라이브 채팅 존재 여부1 단위
요청 방식채팅 1회 조회, YouTube 권장 요청 간격5 단위

스트리밍 방식만 실패하는 경우에도 기본 설정(auto)은 요청 방식으로 전환해 채팅을 수신합니다.

수신 방식

--youtube-mode방식할당량
auto(기본)스트리밍을 우선 사용하고, 사용할 수 없으면 요청 방식으로 자동 전환스트리밍 기준
stream스트리밍(streamList, gRPC). 연결을 유지하며 새 채팅을 즉시 수신연결 1회 5 단위
poll요청 방식(liveChatMessages.list). --youtube-interval 간격(기본 10초, 최소 5초)으로 조회요청 1회 5 단위, 1시간 약 1,800 단위

할당량

  • 기본 할당량은 일일 10,000 단위이며 태평양 시간 자정에 초기화됩니다.
  • 스트리밍은 연결이 유지되는 동안 추가 사용량이 없어 긴 방송에도 적합합니다. 연결이 끊기면 마지막 위치부터 다시 연결합니다.
  • 요청 방식은 기본 간격 10초 기준 약 5시간 분량입니다. 긴 방송은 간격을 늘리거나 Google Cloud에서 할당량 증설을 신청합니다.
  • 스트리밍에는 grpcio, protobuf가 필요하며 설치 프로그램과 실행 파일에는 포함되어 있습니다.

창이 기억한 자리로 가지 않음모니터 연결 확인(연결되지 않은 모니터의 자리는 건너뜀). 창이 늦게 뜨는 프로그램은 켜는 간격을 늘림
VMC로 받은 캐릭터가 움직이지 않음받는 프로그램의 VMC 수신 켜기와 포트 확인, VMC 화면의 보낸 횟수가 늘어나는지 확인. 얼굴 추적 창이나 휴대폰 추적이 켜져 있어야 함
OBS에 넣기가 되지 않음오른쪽 위의 OBS 표시 확인. OBS를 켜고 도구, WebSocket 서버 설정에서 서버 사용을 켜고 비밀번호를 설정 마법사에 입력. 그래도 안 되면 끌어다 놓기 링크나 주소 복사
알림 소리가 방송에 안 나감알림을 OBS에 넣기로 다시 넣기(OBS로 오디오 보내기와 모니터링을 맞춤). 직접 넣었다면 소스 속성의 OBS로 오디오 제어를 켬
디스코드 음성 위젯이 비어 있음이 PC의 디스코드 앱이 켜져 있고 그 음성 채널에 들어가 있는지 확인. StreamKit에서 OBS용 설치를 다시 허락
커뮤니티 올리기 실패화면의 이유 확인. 권한 부족이면 API 토큰에 Workers 스크립트, Workers KV, D1 편집, 계정 설정 읽기 권한이 있는지 확인. 처음 올린 주소는 열리기까지 몇 분 걸릴 수 있음
채팅 인증이 넘어가지 않음오버레이가 실행 중이고 그 플랫폼 채팅을 받고 있는지, 커뮤니티 화면의 채팅 인증이 켜져 있는지 확인. 숫자는 10분 동안만 쓸 수 있음
SmartScreen 경고추가 정보 선택 후 실행. 실행 파일 사용이 어려운 경우 파이썬 패키지로 설치

해결되지 않는 문제는 GitHub 이슈에 점검 결과(설정 마법사 마무리 단계의 점검 결과 복사 또는 debutkit doctor --json)와 함께 등록합니다. 오류 기록 파일(설정 폴더의 logs)을 첨부하면 원인 확인에 도움이 됩니다.

개인정보와 보안

  • 사용 통계를 전송하지 않습니다.
  • 외부 연결은 직접 실행한 경우에만 발생합니다: 업로드 속도 측정(Cloudflare 측정 서버, speed.cloudflare.com에 최대 31 MB의 임의 데이터 전송), 새 버전 확인(GitHub), ffmpeg 다운로드(GitHub), 로고 만들기의 생성형 AI(사용자가 고른 서비스). PC 정보는 전송하지 않습니다.
  • 오버레이 서버는 127.0.0.1에서만 열리며, 다른 웹사이트의 요청은 Host, Origin 확인으로 차단합니다.
  • 뽑기판의 판과 열기 기록(pick.json), 후원 벽의 후원자 닉네임과 금액(wall.json, 시그니처 그림은 wall 폴더), 참여 레이스 설정(race.json, 참가자 명단과 결과는 메모리에만), 방송 색과 방송 스타일(theme.json, 올린 글꼴은 fonts 폴더), 게임 패키지와 프레임 문구(games.json), 알림 꾸미기(alerts.json, 올린 그림은 alert-images 폴더)는 설정 폴더에만 보관하며 외부로 보내지 않습니다.
  • 디스코드 합방 설정과 참여자 그림은 설정 폴더의 discord.json, discord-images 폴더에, 웹후크 주소는 discord-keys.json(암호화)에만 둡니다. 방송 알림은 사용자가 저장한 웹후크로만 보내며 채팅 수, 후원 수, 원으로 바꾼 합계 말고 시청자 이름은 보내지 않습니다.
  • 팬 커뮤니티의 회원과 글은 스트리머의 Cloudflare 계정에 저장되며(국외 데이터센터일 수 있음) debutkit 팀은 볼 수 없습니다. 이 PC에는 커뮤니티 주소와 연동 설정(community.json), Cloudflare 토큰과 커뮤니티 토큰(community-keys.json, 암호화)만 둡니다. 방송 중에는 !인증, !출석을 친 시청자의 플랫폼 계정 번호와 닉네임만 커뮤니티로 보냅니다.
  • 방송 시작 버튼의 세팅(프로그램 경로, 사이트 주소, 창 위치)과 이번 방송에 끈 프로그램 목록은 설정 폴더의 launcher.json, launcher-session.json에만 보관합니다.
  • VMC 송신은 얼굴 추적 숫자 값만 사용자가 지정한 이 PC나 같은 네트워크의 프로그램으로 보내며, 인터넷 주소는 받는 곳으로 지정할 수 없습니다.
  • 채팅은 저장하지 않으며 화면 표시용 최근 30개만 메모리에 유지합니다. 자동 클립의 급증 판단에는 닉네임을 해시로만 사용합니다. 후원 추첨 결과(후원자 이름 포함)도 파일로 저장하지 않고 최근 100개만 메모리에 둡니다. 시청자 참여 추첨 명단도 메모리에만 두며 모집을 새로 시작하면 지웁니다.
  • 치지직 토큰은 이 PC의 사용자 설정 폴더에만 보관합니다. YouTube API 키와 치지직 Client Secret은 실행 중에만 사용합니다.
  • 저장한 설정(채널 주소, 포트, 선택 항목)은 이 PC의 사용자 설정 폴더에만 보관하며 외부로 전송하지 않습니다. API 키, 비밀번호는 저장하지 않습니다.
  • OBS 없이 바로 방송의 스트림 키는 Windows 데이터 보호(DPAPI)로 이 Windows 사용자만 풀 수 있게 암호화해 설정 폴더에만 보관하고, 조작 화면과 기록에는 표시하지 않습니다. 송출 화면과 마이크 소리는 사용자가 지정한 방송 플랫폼 송출 서버로만 보내며 녹화하지 않습니다.
  • 휴대폰 앱의 바로 방송은 스트림 키를 휴대폰 키 저장소(AndroidKeyStore)의 키로 암호화해 앱 안에만 보관하고 백업하지 않습니다. 캐릭터 화면이나 카메라 영상과 마이크 소리는 사용자가 지정한 방송 플랫폼 송출 서버로만 보내며 저장하지 않습니다.
  • 로고 만들기의 생성형 AI는 사용자가 만들기를 누른 경우에만 사용자가 고른 서비스로 심볼 설명, 느낌, 색을 보냅니다(ComfyUI는 사용자가 입력한 주소의 PC로만). 채널 이름은 보내지 않고 이 PC에서 글꼴 윤곽선으로 넣습니다. AI Horde에 키 없이 보낸 설명과 결과 그림은 AI Horde 약관에 따라 LAION 공개 데이터셋에 공유되고, 그림을 그리는 자원봉사자가 설명을 보며, AI Horde는 IP 주소와 설명을 수집합니다(13세 이상 사용 가능). 아이콘과 기본 도형은 외부로 아무것도 보내지 않습니다. API 키는 Windows 데이터 보호(DPAPI)로 암호화해 설정 폴더에만 보관하고(다른 운영체제는 운영체제 키 보관소, 없으면 실행 중 메모리), 화면과 기록에는 표시하지 않습니다.
  • 캐릭터 음성 반응은 OBS가 계산한 마이크 음량 수치만 사용하며 음성을 저장하거나 전송하지 않습니다. 등록한 캐릭터 파일은 이 PC의 캐릭터 보관함에만 둡니다.
  • VTube Studio 연동은 이 PC의 VTube Studio(127.0.0.1)에만 연결하며 토큰은 설정 폴더에만 보관합니다.
  • 웹캠 얼굴 추적은 브라우저 창 안에서 영상을 처리하고 숫자 값만 이 PC의 debutkit 서버로 보냅니다. 추적 화면은 보안 정책으로 이 PC 밖으로의 접속을 차단합니다.
  • debutkit 휴대폰 앱의 카메라 영상 모드는 영상을 같은 Wi-Fi의 OBS 수신 화면으로만 직접 보내며 debutkit 서버는 연결 정보만 전달합니다. 영상은 저장하지 않습니다.
  • debutkit 휴대폰 앱은 카메라 영상을 휴대폰 안에서만 처리하고 서명된 숫자 값만 같은 Wi-Fi의 PC로 보냅니다. 인터넷으로 보내거나 저장하지 않으며 사용 통계를 수집하지 않습니다.
  • 휴대폰 조작 화면은 사용자가 켠 경우에만 이 PC의 내부 네트워크 주소 하나에 열리고, QR로 등록하고 PC에서 승인한 휴대폰의 서명된 요청만 처리합니다. 기기 비밀값은 설정 폴더에만 보관합니다.
  • 휴대폰 카메라 영상은 OBS가 직접 받으며 debutkit을 거치지 않습니다. 암호가 맞는 휴대폰만 연결되고, 영상은 녹화하거나 외부로 보내지 않습니다(방송 송출은 OBS 설정에 따름).
  • 휴대폰 얼굴 추적은 사용자가 연결을 시작한 경우에만 휴대폰과 연결된 네트워크 주소 하나에서 값을 받고, 지정한 휴대폰 IP의 값만 사용합니다. 휴대폰 앱이 보내는 것은 표정과 머리 각도 숫자 값이며 카메라 영상은 오지 않습니다. 값은 저장하지 않습니다.
  • 오류 기록은 설정 폴더의 logs 폴더에 저장합니다(파일당 1 MB, 최근 3개). 처리되지 않은 오류와 상태 안내만 기록하며 채팅 내용은 기록하지 않습니다.
  • 비공식 수신(--chzzk, --soop)은 플랫폼이 승인한 방식이 아닙니다. 본인 치지직 채널은 공식 API 사용을 권장합니다.
